1. 文档目标与使用方式

1.1 目标

本规划把 Cortex 拆成可按顺序执行的编码任务。每个模块给出：

- 待建文件（在 Cortex 应用工程内的路径）
- 要实现的类 / 函数及关键签名
- 复用的框架 API（hello_agents.*，直接 import 使用）
- 自定义扩展点（继承框架基类新增的部分）
- 算法参考（教程 code/chapterX 仅供逻辑参考，不直接拷贝）
- 验收标准（可自测的判定条件）
1.2 核心原则

原则
说明
上层应用，不改框架
hello-agents 以 pip install 引入，Cortex 代码不修改框架源码；所有新能力通过 Tool / Agent / Skill 扩展点接入
工具即能力
记忆、RAG、MCP、A2A 全部封装成继承 hello_agents.tools.Tool 的工具，注册进 ToolRegistry，供 Agent 调用
服务与工具分离
重逻辑（RAG 管线、记忆存储）放在 services/，工具层只做薄封装，便于单测与复用
先跑通再增强
每个 Phase 结束都有可运行的端到端 Demo，禁止一次性堆叠

1.3 使用方式

按 §4 的 Phase 顺序推进；每完成一个模块，对照 §5 的验收标准打勾；§6 给出可并行/强依赖关系；§7 是每层的测试要求。

P3 · KnowledgeService（RAG）

重逻辑放 cortex/services/knowledge/，工具层 knowledge_tool.py 薄封装。算法参考 ch8 04/05/10。

任务 3.1 向量库封装 — services/knowledge/store.py

- 技术：qdrant-client。
- 关键类：VectorStore，方法 upsert(chunks, vectors, payloads)、search(vector, top_k, filter)。
- 实现要点：collection 维度对齐 embedding 模型；payload 存 doc_id/chunk_id/source/text/created_at。
- 验收：能对任意向量做 top_k 检索并带 payload 回传。
任务 3.2 文档摄取管线 — services/knowledge/ingest.py

- 技术：markitdown（PDF/Word/PPT/HTML→Markdown）、分块、embedding。
- 关键函数：ingest_document(path) -> doc_id。
- 实现要点：
  - 解析 → 清洗 → 递归/语义分块（默认 chunk_size=512、overlap=64 tokens，用 tiktoken 计数）。
  - 每块 embedding 后 VectorStore.upsert。
  - 抽取实体/关系写入 Neo4j（见 3.4）。
def ingest_document(path: str) -> str:
    md = MarkItDown().convert(path).text_content
    chunks = chunk_by_tokens(md, size=512, overlap=64)
    vecs = embed_model.encode([c.text for c in chunks])
    store.upsert(chunks, vecs, payloads=[c.meta for c in chunks])
    graph.extract_and_link(doc_id, md)   # 任务 3.4
    return doc_id

- 验收：导入一篇 PDF 后，Qdrant 中出现对应分块；分块边界不截断句子（抽查）。
任务 3.3 高级检索 — services/knowledge/retrieve.py

- 算法参考：ch8 05_Advanced_Search。
- 关键函数：retrieve(query, top_k) -> list[Chunk]，内部串联：
  1. Multi-Query Expansion (MQE)：弱模型改写出 N 条同义 query。
  2. HyDE：让 LLM 生成"假设答案"再 embedding 检索。
  3. 混合检索：向量检索 + BM25/关键词（可选），结果 RRF（Reciprocal Rank Fusion） 融合。
  4. Rerank：bge-reranker-v2-m3 对候选精排取 top_k。
def retrieve(query, top_k=5):
    queries = mqe(query) + [hyde(query)]
    hits = []
    for q in queries:
        hits += store.search(embed(q), top_k=20)
    fused = rrf_fuse(hits)                 # 倒数排名融合
    return reranker.top(query, fused, k=top_k)

- 验收：对知识库问题，rerank 后 top-5 命中率优于纯向量检索（用 §7 小测集对比）。
任务 3.4 知识图谱 — services/knowledge/graph.py

- 技术：neo4j driver；框架依赖已含 networkx（可做本地图分析）。
- 关键函数：extract_and_link(doc_id, text)（LLM 抽取实体/关系）、query_entity(name)。
- 验收：导入文档后 Neo4j 中生成实体节点与关系边；可按实体反查相关文档。
任务 3.5 RAG 工具封装 — tools/knowledge_tool.py

- 复用：Tool + @tool_action。
- 动作：ingest(path)、search(query, top_k)、answer(question)（检索+生成，带引用）。
- 验收：Agent 调用 knowledge.answer 能返回带来源引用的答案。

P4 · MemoryService

参考 ch8 01~03/06/09。仿人类认知分层。

任务 4.1 记忆数据结构 — services/memory/types.py

- 关键类：MemoryItem（id/type/content/embedding/importance/created_at/last_access/access_count/metadata）；枚举 MemoryType = {WORKING, EPISODIC, SEMANTIC, PROCEDURAL}。

任务 4.2 存储后端 — services/memory/store.py

- 技术：SQLite 存元数据/情景，Qdrant 存语义记忆向量。
- 关键类：MemoryStore，方法 add、query(text, type, top_k)、touch(id)（更新访问）、decay()。
- 验收：写入后可按语义检索；touch 更新 access_count/last_access。
任务 4.3 综合评分 — services/memory/scoring.py

- 算法参考：ch8 记忆检索评分。
- 关键函数：score(item, query) = w1*relevance + w2*recency + w3*importance + w4*frequency。
def score(item, query_vec, now):
    rel = cosine(item.embedding, query_vec)
    rec = exp(-lambda_ * (now - item.last_access))     # 时间衰减
    imp = item.importance                               # 弱模型评估的 0~1
    freq = log1p(item.access_count)
    return 0.5*rel + 0.2*rec + 0.2*imp + 0.1*freq

- 验收：高相关+近期+高频记忆排序靠前。
任务 4.4 整合与遗忘 — services/memory/consolidate.py

- 算法参考：ch8 06_Memory_Consolidation。
- 关键函数：
  - consolidate()：把重复/相似的情景记忆用弱模型摘要，升格为语义记忆。
  - forget()：三策略——低分裁剪（score < 阈值删除）、容量上限 LRU、时间衰减（超期且低重要性归档）。
- 验收：多次相似对话后语义记忆条目收敛（不无限膨胀）；低价值记忆被清理。
任务 4.5 记忆工具封装 — tools/memory_tool.py

- 动作：remember(content, type)、recall(query)、forget(id)。
- 验收：跨会话——首会话告知偏好，次会话 Agent 能主动 recall 并应用。

P5 · ContextEngine + 多智能体编排

任务 5.1 上下文引擎 — cortex/context/engine.py

- 复用：hello_agents.context：ContextBuilder、Truncator、TokenCounter、HistoryManager；参考 FW examples/context_engineering_demo.py。
- 实现 GSSC：build_context(task, budget)：
  - Get：拉取系统提示、当前任务、相关记忆（MemoryService）、检索片段（KnowledgeService）、历史。
  - Select：按 §设计文档 的评分贪心填充至 token 预算内。
  - Structure：分区排版（指令/知识/记忆/历史/工具结果）。
  - Compress (Compaction)：历史超阈值时用弱模型摘要压缩。
def build_context(task, budget):
    cands = gather(task)                     # Get：记忆+知识+历史+工具结果
    picked, used = [], 0
    for c in sorted(cands, key=priority, reverse=True):   # Select：贪心
        if used + c.tokens <= budget:
            picked.append(c); used += c.tokens
    if history.tokens > COMPACT_THRESHOLD:   # Compress
        history = summarize(history, weak_llm)
    return render_sections(picked, history)  # Structure

- 验收：长对话下上下文稳定不超窗口；开启 Compaction 后 token 占用显著下降（§设计文档目标 -60%）。
